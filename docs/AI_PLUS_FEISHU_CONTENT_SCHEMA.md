# AI+ 专题：飞书维护与网站数据约定

AI+ 二级专题的静态页面位于 `ai-plus/`，当前读取 `api/ai-plus.json`。现有 `refresh.py` 不修改，也不负责本专题；在飞书表结构和授权确认前，先由该 JSON 提供初始内容。

## 建议的飞书多维表格

### 表一：AI+ 模块

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 编号 | 文本 | `00`–`04`，决定顺序 |
| 标题 | 文本 | AI 概述、日常增效等 |
| URL 标识 | 文本 | `overview`、`office` 等稳定 slug |
| 简介 | 多行文本 | 首页模块说明 |
| 标签 | 文本 | 例如“视觉工作流” |
| 是否发布 | 复选框 | 未勾选不写入 JSON |
| 排序 | 数字 | 同编号下的稳定排序 |

### 表二：AI+ 工具卡（后续扩展）

字段建议：名称、所属模块、类型、适合任务、不适合任务、输入、输出、人工审核、数据/版权边界、讲师实测、官网、学习链接、最后复核日期、状态、排序、是否发布。

### 表三：AI+ 工作流案例（后续扩展）

字段建议：标题、所属模块、项目阶段、问题、脱敏输入、步骤、输出、质量门槛、风险、学习资料、是否发布、排序。

## 同步要求

后续新增独立同步脚本或 GitHub Actions 时，应只更新 `api/ai-plus.json` 及未来的 AI+ JSON 文件：

1. 只读取“是否发布”已勾选的记录。
2. 使用 URL 标识生成网页路径，绝不暴露飞书 record ID。
3. 写入前验证编号、标题、slug、简介、标签和排序。
4. 生成报告；字段缺失时跳过并报告，不生成空卡片。
5. 飞书 App ID、App Secret 与其他凭据仅能存在于 GitHub Secrets 或本机 `.env`，不得写入代码、JSON、文档或提交历史。
