AGENT / DIGITAL WORKER

从回答问题到真正去做事

Agent 智能体不是更会聊天的机器人，而是能够理解目标、调用工具、执行步骤、检查结果并继续推进的数字员工。本页通过 Coze、Codex、QClaw 等平台，建立从概念到实践的认知。

发展路径 Codex 案例
目标被拆成计划。 计划调用工具执行。 结果再被校验与迭代。

Agent 智能体的发展

智能体的关键变化，不在于回答变长，而在于它开始拥有“行动回路”：目标 → 计划 → 工具 → 结果 → 校验。

01 / Chat

回答问题

模型根据上下文生成文字或代码，主要价值是信息理解与内容产出。

02 / Tool

调用工具

智能体开始连接搜索、知识库、表格、浏览器、API 和本地文件。

03 / Loop

连续执行

把复杂目标拆成多个步骤，执行后读取结果，再决定下一步。

04 / Worker

数字员工

在权限、规则和人工确认边界内，长期承担一类可复用工作。

常见智能体平台

平台的区别主要在搭建方式、工具连接、部署渠道和权限边界，而不是“谁更像人”。

Coze / 扣子 可视化搭建

适合用工作流、插件、知识库和多种触发器快速搭建面向业务的 Agent。

  • 适合：内容生产、客服、数据整理、社媒机器人。
  • 特点：低代码、组件丰富、发布渠道多。
  • 注意：上线前检查数据权限和第三方插件边界。

Codex 代码智能体

面向真实代码仓库和开发任务，能够读取项目、编辑文件、运行检查并根据结果继续修改。

  • 适合：网页、脚本、测试、重构、文档和自动化。
  • 特点：工作区上下文、工具调用、可验证产物。

应用实例：用 Codex 做一个网页页面

把“做页面”从一句模糊要求，变成一条可检查的智能体执行链。

案例目标

为个人网站新增一个独立内容页面，并保持原有导航、同步脚本和其他页面不受影响。

上下文

先读取项目结构和既有页面风格，明确哪些是参考内容，哪些是必须沿用的系统边界。

权限范围

只处理目标 HTML 正文和必要样式，不修改 refresh.py，不替换全站导航。

验收标准

检查标签、链接、移动端、无横向溢出，以及页面是否接入顶部二级菜单。

01

读项目

定位当前页面、样式文件、导航脚本和内容来源。

02

改正文

把素材内容转成项目已有组件，而不是复制陌生样式。

03

运行检查

本地预览、检查链接、检查移动端和 HTML 结构。

04

交付迭代

根据反馈微调视觉、文案和交互，确认后再推送。

Agent 最重要的是边界

关键不是“让 AI 自己发挥”，而是给智能体清晰的上下文、权限范围和验收条件。能自动执行，也必须能被人审查。

1

说清目标

不要只说“帮我优化”，要说明最终页面、内容范围、不能碰的文件和预期效果。

2

限定权限

写明是否能联网、是否能改文件、是否能推送、是否能操作外部服务。

3

要求验证

让 Agent 用可复现方式检查，而不是只凭“看起来没问题”。

4

保留决定权

涉及发布、删除、费用、客户资料和外部系统时，最终决定必须由人做。
